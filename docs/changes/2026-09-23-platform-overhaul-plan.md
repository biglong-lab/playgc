## 設計原則（日後驗收用）

1. **一頁一功能**：一頁最多 1 顆主按鈕、標題「動詞＋名詞」；超過 3 個主題拆子頁
2. **設定四要素**：說明、預設值、驗證（前後端共用 zod）、儲存回饋；每個設定鍵都要有讀取點（守護測試）
3. **危險操作三級**：L1 可復原（垃圾桶 + 復原提示）／L2 影響他人（確認框寫影響範圍）／L3 不可逆或全場域（輸入名稱確認 + 原因 ≥5 字 + 稽核）
4. **看不到就打不到**：選單、按鈕、API 判斷同源；死按鈕 = 0
5. **導航單一來源**：由 `admin-menu.ts` 生成側欄、麵包屑、⌘K
6. **指引＝完成度清單**：每一步直接連到要做事的頁；空狀態附「下一步」
7. **積木可拆卸**：模組關掉 → 選單、API、cron 同時停
8. **未存不丟**：攔截站內換頁；預覽讀草稿

## 經銷合作模型（對照 hung-blocks L0–L4）

- L0 partners 積木程式碼（所有經銷共用）／L1 每家經銷可開通的模組／L2 品牌、專屬連結、預設方案、分潤比例（資料）／
  L3 經銷只看得到授權場域／L4 客製邏輯走 webhook 訂閱事件；白牌延後
- 四件套：`server/modules/partners/{index.ts, server/}`、`shared/schema/partners.ts`、`client/src/pages/partner/`；守護：外部禁止 import 內部檔
- 新表（全部只加不刪）：partners、partner_members、partner_fields（解除寫 detached_at 不刪列）、partner_leads、partner_commissions（platform_transaction_id 唯一 → 冪等）；
  field_applications 加可空 `partner_code`
- 權限：不新增 systemRole；經銷在客戶場域建一筆 admin_account，套「經銷報表／經銷協助／代管」三種預設角色；
  放寬 switch-field：同一 firebaseUserId 在目標場域有 active 帳號即可切（多館業主也受惠）
- 開通：`/p/:slug` 品牌落地頁 → `/apply?ref=CODE` → 平台審核呼叫共用 `provisionField()`（合併兩套建場流程、補建預設角色與申請人帳號）→
  事件 `field.provisioned` → partners 寫授權、lead 標 won → Resend 開通信
- 分潤：來源 platform_transactions 已付款的訂閱與抽成；月結產 partner_commissions（冪等）；平台核准後人工匯款標 paid；平台沒收到錢不產分潤
- ADR：0026 經銷夥伴模型／0027 權限鍵拆分與模組開關後端化／0028 導航單一來源與設定中心／計費閉環另寫（對照 ADR-0006）
